## Source quality

| Source | Problem | Corroborate via |
|---|---|---|
| AgenticAIFrameworks | Personal POC scripts, early-to-mid 2025 APIs, little error handling; several examples unfinished (deep research implements only the scope phase) | The framework's own docs |
| AutoGen course | pyautogen 0.2 API; AutoGen has since been rewritten (0.4) and superseded by Microsoft Agent Framework | Current AutoGen / Agent Framework docs |
| Letta course | Pinned to `letta==0.6.50`; the client API has changed in later releases | Letta docs |
| Lakshmanan & Hapke | Point-in-time numbers ("3–10 tools as of June 2025", MCP limits as of May 2025, including the 30–60 s call timeout). Ch. 7's 40–80% multi-agent failure figure is quoted from Cemri et al., not measured; its code uses legacy `LLMChain`/`SequentialChain` and `create_react_agent`. Ch. 10 has no measurements; its retry rule (>90% success → <1% failure with retries) assumes independent failures, and its Gemini 2.5 model names are mid-2025. Ch. 1 says models "employ beam search", which is wrong as a general claim for hosted LLMs, which sample. Ch. 5's oil example yields a flow of about 84 m³/s and a velocity near 1700 m/s, which the model itself calls very high. Ch. 9 equates logprobs with logits, its `apply_guardrails` signature is inconsistent, and the Table 9-2 caption is wrong | Current provider docs and the MCP spec |
| Albada, *Building Applications with AI Agents* | Ch. 2 misdescribes MCP as injecting context "without invoking separate tools", unlike API calls that need a round trip; MCP tools are `tools/call` round trips (corrected in [02](notes/02c-mcp-code-and-safe-tool-calls.md#mcp-tools-served-over-a-protocol)). Table 2-1 contradicts its own text: it says models up to ~14B fit a 24 GB RTX 3090, yet lists Phi-3 at 14.7B / 29.4 GB needing an A100, and its "full precision" VRAM is ~2 bytes/param (fp16). Ch. 2 code listings have syntax errors. Price and HELM tables are mid-2025 snapshots A listing assigns `AIMessage=...` and then uses an undefined `first`, and the eval example asserts on content rather than `tool_calls`. | The MCP spec; current price pages and leaderboards |
| Koenigstein, *AI Agents: The Definitive Guide* | Early Release, still changing. Calls `AgentExecutor` "often preferable in production" (legacy) and uses `create_react_agent` (deprecated in LangGraph 1.0 for `langchain.agents.create_agent`). Ch. 4 passes `rope_scaling` to a ModernBERT load call as a way to extend context, which is model-dependent and not a free 4× context gain. Examples use `gpt-4o`; o1-pro pricing is dated. The same listing puts an encoder model behind `generate`, and a relevance score is described as self-auditing | LangChain/LangGraph 1.x docs; model cards |
| Oshin & Campos, *Learning LangChain* | Ch. 6 calculator uses `ast.literal_eval`, which rejects arithmetic such as `"1933-1872"`, and the model's own subtraction gives Coolidge's age as 61 (it was 60). Ch. 7 Python supervisor: `AgentState` lacks `messages`, and `"FINISH"` isn't mapped to `END` (the JS version is correct). `gpt-3.5-turbo` examples | Run the code; LangGraph docs |
| Phoenix & Taylor, *Prompt Engineering for Generative AI* | 2024 LangChain APIs: `AgentExecutor`, LCEL agents, hub prompts, `Conversation*Memory` classes (deprecated in favor of LangGraph persistence). Table 6-2 says function calling lacks sequential tool execution; native tool-calling loops do sequential and parallel calls | LangChain/LangGraph docs |
| Raieli & Iuculano, *Building AI Agents with LLMs, RAG, and Knowledge Graphs* | Ch. 4 code uses `initialize_agent` with `zero-shot-react-description`, `langchain.utilities` and LangServe, all legacy. Ch. 11's single- vs multi-agent table carries the caption "Potential causes of multi-agent system failure". Ch. 11 dates Jiang et al. to 2022 though it is arXiv 2406, and "incapable of reasoning" is opinion | The cited papers (Cemri, Sprague, Mirzadeh, Gao, Bansal, Mitchell) |
| Note 06 (Kaggle course) | Course notes from a Notion export, Days 1–3 only. Claims such as the 80% problem, "most agent failures are configuration failures" and "multi-agent systems are losing favor" are the course's framing, not measurements | The Kaggle whitepapers; [04](notes/04-multi-agent-design-patterns.md) for the multi-agent evidence |
